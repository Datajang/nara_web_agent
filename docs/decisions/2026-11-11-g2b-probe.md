# G2B 실제 응답 확인 (P1 [미확인] 항목)
- 명세 위치: §4 정정공고 차수, §5.2 numOfRows 최대값, §5.6 다운로드·허용 호스트
- 방법: `backend/scripts/probe_g2b.py` (G2B 10회 호출, 2026-11-10 하루치). 녹화본 `backend/tests/fixtures/g2b/` (키 마스킹, 5건으로 축약)
- 결과:
  - numOfRows 999 허용(하루 846건 1회에 반환). 키워드 없이 날짜 구간(`inqryDiv=1`)만으로 전체 조회 가능. 하루 일반공고 846건, 사전규격 421건
  - 같은 `bidNtceNo`가 차수 `bidNtceOrd`(000~003)별로 한 응답에 여러 줄. `ntceKindNm`: 등록공고 642, 재공고 104, 변경공고 42, 취소공고 58
  - 오류 응답 2종: 기간 초과는 HTTP 200 + `nkoneps.com.response.ResponseError.header.resultCode=07`, 잘못된 키는 HTTP 403 + `OpenAPI_ServiceResponse.cmmMsgHeader`
  - `items`는 list로 내려옴(dict·"null" 형태도 계속 처리). 날짜는 `YYYY-MM-DD HH:MM:SS`, `bidClseDt`는 빈 문자열일 수 있음. 일반공고 예산은 `bdgtAmt`가 비고 `presmptPrce`·`asignBdgtAmt`가 있음
  - 첨부 URL 3,238개 모두 `https://www.g2b.go.kr`. httpx(인증서 검증 켬, 리다이렉트 없음)로 200 응답, 파일명은 `Content-Disposition`(URL 인코딩)
  - e발주 첨부 API: 첨부 없는 공고 1건에 대해 0건(표본 부족)
- 결정:
  - 페이지 크기 999. 90일 backfill은 약 200회 호출로 추정(예산 500 이내)
  - `bid_key=regular:{bidNtceNo}` 유지. 같은 키는 **차수가 가장 큰 행만** 반영하고, 저장된 차수보다 낮은 행은 무시(역순 도착 대비). `revision`은 §4대로 내용 변경 시 +1
  - 두 오류 형태 모두 재시도 없는 `G2BError`. 다운로드는 httpx + 인증서 검증, 허용 호스트 기본값 `www.g2b.go.kr`
- 명세 수정 필요: 있음 — §4에 취소공고 표시 방식 없음(현재는 `raw.ntceKindNm`에만 남음, 사용자 확인 필요). §5.2 numOfRows 기본 100 → 999
