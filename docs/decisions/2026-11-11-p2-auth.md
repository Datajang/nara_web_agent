# P2 회원·프런트 골격에서 정한 것과 확인한 것
- 명세 위치: §9, §10, §13.4 (사용자 승인으로 §6.1·§6.2·§7.9·§7.10 추가로 읽음)
- 결과·결정:
  - **로그인 잠금(사용자 결정, 추천안 A)**: 실패 횟수를 이메일 sha256 기준 `login_failures` 테이블로 셈(마이그레이션 0003, `users.failed_login_count`·`locked_until` 삭제). 없는 이메일도 5회 뒤 똑같이 429 `account_locked` + Retry-After → §9.8-3 열거 방지와 §10.8 `auth.locked` 문구를 함께 만족
  - 5번째 실패 응답은 401이고 그다음부터 429. 잠긴 동안은 비밀번호를 검사하지 않음(맞는 비밀번호인지 새지 않게)
  - 상태별 거부: 비밀번호가 맞은 뒤 403 `email_not_verified`·`pending_approval`·`disabled`(§9.1). 이미 받은 access로 요청하면 403 `forbidden`(details에 상태)
  - 가입: 비밀번호 해시를 계정 유무와 무관하게 계산(응답 시간 차이 완화), `ON CONFLICT DO NOTHING`으로 동시 가입 경합 처리, 메일 실패는 응답을 바꾸지 않고 경고 로그만
  - **엔드포인트 추가** `POST /auth/verify-email/resend`(§7.10 "재전송 버튼"에 필요, §6.2 표에 없음). 202, 계정 유무와 무관
  - `POST /auth/logout`은 refresh 쿠키만으로 동작(공개). access가 만료된 뒤에도 로그아웃되게. §6.2는 '회원'
  - `POST /auth/refresh`도 `me`를 돌려줌. 비활성 사용자의 refresh는 가족 폐기 후 401
  - 비밀번호 변경(`PATCH /me`): 전체 세션 폐기 후 현재 기기에만 새 세션 발급. 틀린 현재 비밀번호는 400 `invalid_password`
  - 관리자 PATCH: status는 `active`·`disabled`만, 미인증 계정을 관리자가 활성화하면 인증을 대신한 것으로 기록. 비활성화하면 refresh 전부 폐기
  - 흔한 비밀번호: SecLists `10k-most-common.txt`(MIT). 10자 이상은 51개뿐이라 실효는 작음 [가정 유지]
  - 속도 제한: §6.1 표대로 인메모리 토큰 버킷(워커 1개 전제). 테스트는 기본 끄고 별도 테스트로 확인
  - 시작 검사(ENV=production): 기본·32바이트 미만 SECRET_KEY, smtp 아닌 메일, SMTP_HOST·MAIL_FROM 누락, http APP_ORIGIN, COOKIE_SECURE=false면 시작 거부
  - 로그 마스킹 확장: `password`·`token`류 key=value·JSON 값, JWT 형태 문자열. console 메일러는 logging이 아니라 stdout(개발 전용, 운영에서는 시작 거부)
  - **MAIL_BACKEND=memory**(P2 지시): 테스트와 브라우저 확인에 사용. `GET /api/v1/_dev/mail`은 ENV=development + memory일 때만 등록(라우트 테스트로 고정)
  - OpenAPI: `backend/scripts/export_openapi.py` → `frontend/src/api/openapi.json` → `npm run gen:api` → `schema.d.ts`. 최신 여부는 pytest와 CI 단계 둘 다 검사
  - openapi-typescript 7.13의 peer가 TS 5라서 `package.json` overrides로 TS 6을 씀(생성 결과 정상)
  - FastAPI 0.162는 include_router를 지연 포함해 `app.routes`에 하위 라우트가 안 보임 → `iter_routes()`로 순회. 처음엔 라우트 검사 테스트가 빈 목록으로 통과하고 있었고, 최소 개수 단언을 추가해 막음
  - 폰트: npm `pretendard` dynamic-subset을 Vite가 묶어 같은 출처에서 제공(§10.2의 public/fonts 복사 대신, CSP 'self' 충족)
  - SSE 이벤트 형식은 §6.4를 읽지 않아 `data:` JSON의 `type` 또는 `event:` 줄 둘 다 받게 구현 → P3에서 §6.4와 대조
  - 사이드바 메뉴 6개는 §7.1을 읽지 않고 §7.3~7.9 경로로 정함(검색·추천·어시스턴트·내 기록·설정·관리자)
- 브라우저 확인(Debian 11): Playwright 1.65는 debian11용 Chromium이 없어 `PLAYWRIGHT_HOST_PLATFORM_OVERRIDE=ubuntu22.04-x64`로 headless shell을 받고, 없는 `libgbm.so.1`은 Debian `libgbm1_20.3.5-1` .deb를 임시 폴더에 풀어 `LD_LIBRARY_PATH`로 지정(sudo·시스템 변경 없음). 스크립트 `frontend/e2e/p2-auth-flow.mjs`, 22항목 통과
- 명세 수정 필요: 있음 — §4 users에서 실패 횟수 열 제거 + `login_failures`, §6.2 resend 추가·logout 권한, §9.7 `MAIL_BACKEND`에 memory, §10.2 폰트 배치
