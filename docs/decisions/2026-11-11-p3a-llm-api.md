# P3a 백엔드(요약·분석·추천·어시스턴트·API)에서 정한 것
- 명세 위치: §5.7, §6, §8, §13.5 P3a
- 사용자 결정(2026-11-11): 가짜 LLM으로 마감, 골든셋·실제 vLLM 스모크·§8.8-1·2·4·5 실측은 **P3a-2**로 분리. '수집 중'·취소공고·§6.3 정렬·의존성은 추천안대로
- 결과·결정:
  - **LLM 계층**: 클라이언트는 원문 텍스트만, 검증·repair는 `llm/structured.py`(가짜로도 repair 경로 시험). openai SDK 재시도 끄고 직접 2회(5xx·타임아웃·연결), 400 컨텍스트 → `LLMContextTooLong`. 요청마다 `enable_thinking: false`
  - `LLM_BACKEND=vllm|fake|none`(fake는 운영 시작 거부), `LLM_MODEL_ID=q35-9b` → `PROMPT_VERSION v1+q35-9b`. 새 환경변수: `LLM_MODEL_ID`, `LLM_BACKEND`, `LLM_TOKENIZER_PATH`, `LLM_LOCK_WAIT_S`, `SEARCH_FILL_WAIT_S`, `SUMMARY_MAX_CHUNKS`
  - **청킹**: "입력 예산 이하이면 map 없이"를 "나누지 않고 한 청크"로 해석 → 첨부 1개 공고 = map 1 + reduce 1 + 분석 1. 청크 상한은 공고 전체 기준 12개
  - 글자가 200자 미만인 문서는 건너뛰지 않고 경고만(스캔본 가능성). 빈 본문만 건너뜀
  - coverage는 서버가 센 값으로 덮어씀. evidence는 공백 정규화 후 원문 부분 문자열이 아니면 null
  - 프롬프트 구분자 안 데이터의 `<document>` 같은 태그는 전각 괄호로 무력화. 어시스턴트 프롬프트는 '데이터 지시 무시' 줄을 맨 앞으로 옮김(§8.5 공통 규칙)
  - **SSE**: 작업은 별도 태스크(끊겨도 계속), usage_logs는 `done` **전에** 기록. 오류 코드 `llm_unavailable`·`llm_invalid_output`·`llm_error`·`in_progress`·`internal_error`. 이벤트 모델을 OpenAPI `SseEvent`로 내보냄
  - LLM이 아예 없으면(`deps.llm is None`) 스트림 전 503. 설정됐는데 죽어 있으면 스트림 안에서 `error(llm_unavailable)` (매 요청 헬스체크 안 함)
  - **'수집 중'**: 커버리지 밖이면 fill을 `SEARCH_FILL_WAIT_S`(5초)만 기다리고 `collecting: true`로 응답, 늦은 G2B 호출은 끝난 뒤 `usage_logs(event=collector)`로 기록·정산
  - **취소공고**: 카드에 `cancelled`(raw `ntceKindNm == '취소공고'`), 진행중 필터에서도 남김
  - **검색 형식**: §6.3대로 `match`·`days 1~90`·`from/to`·`limit≤100`·`extra=forbid`. 빈 문자열 키워드 422, 빈 목록은 허용(최근 공고 보기). 기본 `status=open`, `days=14`
  - 502 `g2b_error`는 만들지 않음: fill 실패와 상한 도달을 구분하지 않고 `incomplete: true`로 답함
  - `GET /bids/lookup`은 DB만(bid_no 또는 사전규격 등록번호). G2B 단건 조회는 [미확인] 그대로 → 확인 스크립트는 후속
  - 추천: 후보 = 프로필 키워드 OR·진행중·최신 순 최대 300건 [가정], 점수 내림차순 top_n(≤50), `search_runs(kind=recommend)`에 점수·이유 저장
  - 어시스턴트: 스트리밍 중 b-ID 필터(조각 경계 보류), 이번 턴 도구 결과에 없는 ID는 본문·저장·카드 모두에서 제거하고 `parts.warnings`. 이전 턴 ID도 신뢰하지 않음. 도구 상태 stage는 §6.4 목록 안에서 매핑(search·analyze·score)
  - `/readyz`(루트): DB 불가면 503, LLM만 불가면 200 + `llm: unavailable`. `suggest-keywords`에 분당 10회 제한 추가(§6.1 표에 없음)
  - 카드에 `score`·`reason`(추천에서만)·`revision`(정정 배지), 검색 응답에 `collecting` 추가
  - §7을 읽고 P3b 화면에 필요한 것을 보탬: 상세 `prespec_reg_no`·`related_bid_id`, 분석 기록 `profile_name`, `/admin/collector/runs`에 소스별 `coverage`(기본 20건), 사용량 입력·출력 토큰 분리. 추천 후보 상한은 §7.4대로 300건 [가정]
- 명세 수정 필요: 있음 — §6.3 SearchResult `collecting`·BidCard `cancelled/score/reason`, §6.2 lookup은 DB만·readyz 판정·suggest-keywords 제한, §6.1 502 미사용, §8.3-2 해석, 부록 A 새 환경변수
