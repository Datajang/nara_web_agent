# P3b 화면(검색·상세·추천·어시스턴트·내 기록·설정·관리자)에서 정한 것
- 명세 위치: §7, §10, §13.5 P3b
- 사용자 결정(2026-11-11): 관리자 사용량·수집기 화면 포함, 대화별 프로필 변경은 백엔드 `PATCH /conversations/{id}`에 `profile_id` 추가(화면만 원칙의 예외), e2e는 `LLM_BACKEND=fake` + 첨부 허용 호스트 비움(외부 호출 없음)
- §7.0 MCP 패리티 (원본: GitHub Datajang/narajangteo_mcp_server `src/nara_server/server.py`, 읽기만)
  | MCP 도구(인자) | 웹 입력 | 차이 |
  |---|---|---|
  | `get_bids_by_keyword(keyword, days=7)` | 검색: 키워드 칩, 기간 7~90일·직접 선택 | 일반·사전규격 함께(구분 '전체' 기본), 진행중 기본. 일치 방식·예산·기관·정렬 추가 |
  | `recommend_bids_for_dept(keyword, department_profile, days=7)` | 추천: 키워드 직접 지정(선택), 프로필, 기간 | 기간 프리셋은 §7.4대로 7·14·30(MCP는 90까지 예시). 결과 60건(30+30) → 상위 10·20·30 |
  | `analyze_bid_detail(file_url, filename, department_profile="")` | 상세: 공고 ID로 첨부 전부를 자동, 프로필 선택 | URL·파일명 대신 b-ID(규칙 6). MCP는 프로필 없이도 분석 → 웹은 프로필 필수(없으면 만들기 안내) |
  누락된 MCP 인자 없음(추천 90일만 프리셋 밖 — API는 1~90 허용)
- 결과·결정:
  - SSE 이벤트 타입을 프론트에서 쓰려고 OpenAPI `SseEvent` discriminator에 `mapping` 추가(없으면 openapi-typescript가 type을 스키마 이름으로 만듦)
  - 관리자 경로의 비관리자: 리다이렉트 대신 주소 유지 + 403 화면(AppShell). 기존 라우터 테스트 기대값 변경
  - 어시스턴트 `action(open_tab)`: 자동 이동 대신 말풍선 아래 버튼. 누르면 `?prefill=1`로 조건만 채우고 검색은 실행하지 않음(§7.6 "이동만")
  - 검색 '수집 중'이면 4초 간격으로 최대 5번 다시 조회. 분석 `in_progress`는 5초 뒤 자동 재요청
  - 상세는 `?analysis=` 또는 이 공고의 내 최근 분석을 자동으로 보여 줌(탭을 닫았다 다시 열기 §7.11-6)
  - 서버 상태는 `@tanstack/vue-query`, `stores/assistant.ts`는 만들지 않음(대화 화면 상태로 충분)
  - 마크다운은 marked + DOMPurify(img·iframe·form 금지, 링크 새 탭), `MarkdownView` 한 곳만 v-html
  - 차트는 chart.js + vue-chartjs, 사용량 화면 청크에서만 로드. 초기 JS 약 63KB gzip(§10.9 250KB)
  - npm audit: 운영 의존성 0건, 개발 도구(glob·minimatch) moderate 16건은 그대로(강제 수정 시 도구 깨짐)
- 브라우저 확인: `frontend/e2e/p3b-flow.mjs` 46항목 통과(관리자 계정은 환경변수). 끝난 뒤 개발 DB에서 e2e 계정·fake-dev 결과 삭제, 첨부 상태 원복
