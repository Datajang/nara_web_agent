# P4a 운영 마감 — 포트·경로·보안 점검 결정 (2026-11-11)
- 명세 위치: §11 전체, §9.5, §12.3·§12.7·§12.8, `docs/v1/DEPLOY_CUTOVER.md`의 [미확인] 포트·경로
- 확인(읽기 전용, sudo 없음): OS Debian 11. 리슨 127.0.0.1:8000(다른 프로세스)·8001(v1 API)·0.0.0.0:5432(시스템 PG13)·127.0.0.1:5433(개발 Docker PG16). nginx·certbot 미설치, `/etc/letsencrypt` 없음, v1 `nginx.conf`는 `your-domain.com` 틀. 외부 IP 역방향 DNS는 GCP 기본값, Cloud DNS·방화벽 조회는 VM 권한 부족. **도메인 없음**. v1 유닛에 `HTTPS_PROXY`(G2B 접속용) 있음, v1·v2 유닛 이름이 같다.
- 결정(사용자 "추천대로"): API `127.0.0.1:8010`, vLLM `8011`(P0-b 측정 포트), 경로는 명세대로 `/opt/nara`, DB는 PGDG PG16 `5434`. v1과 나란히 띄우고 v1 유닛은 `nara-v1-*`로 보존(CUTOVER §1). GitHub Actions 자동 배포는 미룸. v1 사용자 이전 없음(새 가입). 백업 외부 보관은 버킷이 정해지면 `BACKUP_GCS_URI`.
- 구현 차이:
  - XFF: 명세 §11.4는 "첫 값 신뢰" + `$proxy_add_x_forwarded_for`인데, 그러면 클라이언트가 보낸 값이 첫 값이 되어 속도 제한·로그인 잠금 IP를 위조할 수 있다. nginx는 `$remote_addr`로 덮어쓰고 앱은 127.0.0.1·::1에서 온 요청의 **마지막 값**만 믿는다.
  - `/readyz`에 `collector`(ok/stale/never)·`collector_last_ok_at` 추가. DB가 살아 있으면 200(수집 지연은 경보가 잡음).
  - 경보: `app.ops.check` + `nara-alert.timer`(10분), `ALERT_EMAIL`·`ALERT_*` 설정 추가. 6시간 재발송 억제.
  - 피드백 사유: 마이그레이션 0004(`reason`·`model`·`prompt_version`, 👎만 사유). 집계는 새 경로 대신 `GET /admin/usage`의 `feedback`(§9.4 관리자 경로 범위 유지).
  - 로그: `LOG_FORMAT=json`, 요청 ID 미들웨어(`X-Request-ID`), 경로만 기록(쿼리스트링 제외), uvicorn 접근 로그 끔.
  - vLLM 키는 인자 대신 `/etc/nara/vllm.env`의 `VLLM_API_KEY`(ps 노출 방지). 백업은 `PGPASSWORD`로만.
- 보안 점검(§9.5): npm 운영 0건(개발 16건 moderate). pip-audit: langchain 계열 7개 패키지, 고유 11개(중복 포함 18건). 사용자 결정: teddynote는 필수(olefile은 품질 부족 확인됨). 시험 결과 수정 버전은 모두 langchain-core 1.x가 필요하고 teddynote 0.5.4는 `langchain.schema`(0.x 전용)를 써서 1.x에서 HWPLoader import가 깨지며, extractor는 이때 **조용히 olefile로 떨어진다**. → 11개를 근거와 함께 `backend/security/pip-audit-accepted.txt`에 수용, CI는 그 밖의 취약점에 실패, `test_hwp_dependency_guard.py`가 HWPLoader 사용 가능·앱의 langchain import가 HWPLoader 하나뿐임을 고정, Dependabot은 langchain 메이저 업데이트 제외.
- 외부 접속(사용자 결정: 도메인 미정이지만 외부 접속 필요): 운영은 HTTPS 강제라 IP 기반 임시 주소 `<IP를 -로>.sslip.io` + Let's Encrypt. `deploy/set-host.sh <주소>`가 nginx·인증서·APP_ORIGIN을 한 번에 바꾸므로 도메인이 정해지면 같은 명령으로 교체. 외부 IP 고정·방화벽 80/443은 gcloud 권한이 있는 곳에서(INSTALL §6). sslip.io는 외부 DNS 서비스 의존이다.
