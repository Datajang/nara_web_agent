# P6 팀·관심 공고·팀 분석 공유
- 명세 위치: §13 P6(새로 추가), §7.1, §9.4
- 질문: 관심 없는 공고가 홈에 섞이는 문제와 팀원끼리 분석 결과를 다시 만드는 낭비를 어떻게 줄일까
- 확인: 홈 목록 자체는 G2B를 부르지 않는다(수집기가 날짜 구간으로 전체를 받아 DB에 쌓음, 개발 DB 기록: 수집 181회·검색 보충 11회). 그래서 수집 범위는 그대로 두고 화면 쪽만 키워드로 거른다
- 결정(사용자 승인 2026-11-12, 구현):
  - 팀은 관리자 없이 회원이 만들고 초대 코드(헷갈리는 글자 뺀 10자)·링크 `/join?code=`로 초대. 한 계정 한 팀(`users.team_id` 열 하나). 팀장만 이름 변경·코드 재발급·내보내기·팀 프로필 삭제, 팀장이 나가면 먼저 들어온 팀원이 잇고 혼자면 팀 삭제
  - 키워드 = 팀 프로필 키워드 ∪ 개인 `interest_keywords`, 3개 미만이면 `/onboarding`. `GET /feed`는 키워드 안 단어 AND·키워드끼리 OR, 진행 중·최근 30일, 마감 임박 순
  - 분석 공유는 "팀 프로필로 만든 분석"만(개인 프로필 분석은 본인만). 같은 공고·같은 팀 프로필이면 원래 `analyses` 캐시로 다시 계산하지 않음
  - 팀원 목록에 이메일을 싣지 않는다(이름만). 팀이 없어도 개인 키워드·개인 프로필로 쓴다
- 마이그레이션: `0005_teams`(teams, users 4열, profiles.team_id·user_id NULL 허용·CHECK 하나만). 기존 프로필은 개인 프로필로 남음
- 시험: `test_teams.py`(9)·`test_feed.py`(3)·`test_team_analyses.py`(2), 프론트 `teams.test.ts`(11), e2e 스모크에 키워드→홈→팀 만들기 추가(로컬 통과)
- 남은 것: 초대 수락 e2e(두 번째 계정 필요), 팀 이름 중복 허용(의도), P7 디자인 개편에서 새 화면 다듬기
