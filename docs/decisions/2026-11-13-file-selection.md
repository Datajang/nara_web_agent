# 요약에 읽을 첨부 고르기 — 과업 문서 이름 넓히기, 공고서 대체, 한 문서 한 형식 (2026-11-13)
- 명세 위치: §5.6-6 분류, §5.7 source_hash, §7.5 분석 안내 배너, §8.5 summarize_bid
- 질문: R26BK01819243에서 첨부(공고서 hwpx·pdf)를 받아 글자까지 뽑았는데 "첨부 문서를 읽지 못해"가 뜨고,
  핵심 요구사항마다 "근거: summary"가 붙는 이유
- 확인(개발 DB, 일반공고):
  - 요약은 이름에 '제안요청'·'과업지시'가 있는 첨부(rfp)만 읽었다. 첨부 있는 일반공고 35,975건 중
    **11,717건(1/3)**이 그런 첨부가 없어 첨부를 하나도 안 읽음(과업내용서·수행지침서·입찰공고문 등)
  - 분석 입력은 요약 JSON이라 모델이 근거 파일명 자리에 'summary'를 적고, 그대로 화면에 나감
  - '첨부 문서를 읽지 못함' 경고는 프롬프트가 모델에게 쓰게 한 문구라, 읽을 문서가 없던 경우와 구분이 안 됨
- 결정(사용자 승인 2026-11-13, PROMPT_VERSION v7):
  1. rfp 이름에 과업내용·과업설명·과업명세·수행지침 추가(띄어쓰기 무시). 단 신청서·양식·설명회 안내 등은 제외
     ('5. 과업설명참가신청서' 실데이터 오탐). 기존 행은 alembic 0006으로 다시 매김(약 3,159개·3,048건)
  2. rfp·spec 중 받은 게 없으면 공고서·공고문(서식 제외)을 대신 읽는다. 같은 이름의 hwpx·pdf 등은 하나만
     (받은 것 먼저, 그다음 hwpx > hwp > docx > doc > pdf)
  3. 근거(source)는 실제로 읽은 파일명일 때만 남긴다(확장자 빠진 이름은 실제 파일명으로). 요약·분석 모두
  4. 첨부 경고는 서버가 넣는다: 읽을 첨부는 있었는데 실패 → '첨부 문서를 읽지 못함',
     읽을 첨부가 없음 → '요약할 제안요청서·과업 문서가 없음'. 화면 배너 문구도 둘로 나눔
- 영향: 읽는 문서가 늘어 요약 시간·GPU 사용이 그만큼 는다. source_hash가 바뀐 공고는 요약을 새로 만든다
