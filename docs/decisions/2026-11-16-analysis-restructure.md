# 분석 결과 개편(v10)과 진행 로딩바 (2026-11-16)
- 설계: `docs/superpowers/specs/2026-11-16-analysis-restructure-progress-design.md` (사용자 승인)
- 명세: §6.4(status progress·expected_s), §7.5-4(로딩바), §7.5-5(분석 순서), §8.4(스키마), §8.5(analyze_bid)
- 질문(사용자): 요약과 분석이 겹친다(요구사항·평가·일정·예산). 분석은 '어떤 사업인지'와 프로필 기준
  '우리 팀에 필요한 것'(객관적 판단)을 다루고, 프로필이 부족하면 간략히 + '더 상세히' 안내. 시간 로딩바.

## 결정
- 분석 = 사업 이해(목적·과업 범위·수행 조건) → 적합도 → 우리 팀에 필요한 것(갖춘 것/보완할 것)
  → 리스크 → 다음 할 일. 팀 소개 200자 미만이면 `profile_brief`(서버가 정함), have·need 각 3개 이하.
  `profile_missing`(판단에 필요한데 프로필에 없는 정보)이 있거나 brief면 안내 + [프로필 고치기].
- 예전 분석(v9 이하)은 `LegacyAnalysisResult`로 계속 읽고 옛 화면으로 보여 준다.
- 요약 `scope`는 조각별 FileFacts.scope를 서버가 합친다: reduce 출력에 넣으면 최악 출력
  4,208토큰 > 4,000.
- 수행 조건에 금액·날짜가 있으면 서버가 뺀다(실모델 b565 '2027년 1월 29일까지 완료').
- 로딩바: 파일·추출 5·10% → 요약 조각 done/total로 10→70% → 합치기 70→75%(첫 조각×1.5 예상)
  → 분석 expected_s(90초, 골든셋 중앙값 89초) 동안 75→95%. 남은 시간은 길게 잡고, 넘기면 '거의 다 됐어요'.
