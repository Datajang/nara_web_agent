# 낙찰·계약 API 실제 응답 확인 (P8-a)
- 명세 위치: §15.10 확인할 것 1~8, §15.2~§15.4
- 방법: `backend/scripts/probe_awards.py` (G2B 33회 + `--joint-only` 7회 = 40회, 2026-11-16). 응답은 저장소 밖에 개인정보 필드를 지우고 저장, 녹화본 5건씩 `backend/tests/fixtures/g2b/awards_*.json`·`opening_compt_page1.json`·`contracts_page1.json`
- 대조 DB: 개발 DB `bids` 39,009건(공고일 2026-08-02~11-10, 모두 신체계 13자리)

## 결과
1. **공고번호 형식**: 최근 2주 낙찰 3,390건 모두 신체계 `R26BK…` 13자리, `ntceDivCd`는 전부 `통050001`. 3,247건(95.8%)이 `bids.bid_no`와 그대로 일치(나머지는 수집 이전 공고). 차수는 `bids` 최대 차수와 3,246/3,247 일치. 5년 전(2021-11) 낙찰은 구체계 11자리 숫자(999/999). 자체조달 형식은 표본에 없음. 마감이 지난 `bids` 20건 중 13건이 낙찰 창에 있었고, 나머지 7건은 번호 조회(`inqryDiv=4`)도 0건(아직 낙찰 전·유찰)
   - 한 공고에 `bidClsfcNo`(분류) 0·1, `rbidNo`(재입찰) 000~003이 있다. 2주치에서 `(공고번호, 차수, 사업자번호)` 중복은 0건
2. **조회 기간**: 시작~끝이 7일 미만(예: 6일 23시간 59분)이면 정상, **정확히 7일·8일·31일은 HTTP 200 + `nkoneps.com.response.ResponseError` resultCode 07 '입력범위값 초과 에러'**. `numOfRows=999`는 999행, **`1000`은 오류 없이 기본값 10행만 돌려준다**(조용히 잘림)
3. **건수**: 최근 7일 창(등록일시 `inqryDiv=1`) 1,741건 → 999행 2페이지. 그 전 주 1,649건. 같은 창을 개찰일시(`inqryDiv=3`)로 보면 857건
4. **협상에 의한 계약**(667건): `sucsfbidAmt`는 667/667 채워짐, **`sucsfbidRate`는 56/667만**(그 밖 방식은 2,535/2,580). 개찰완료 목록(5건 호출)은 협상이면 `techEvlVal`·`bidPrceEvlVal`·`totalEvlAmtVal`이 모두 채워지고 `bidprcrt`는 대부분 비며, `opengRank`는 일부 업체만. 협상이 아니면(2건) 점수가 비고 `bidprcrt`가 있다. 개찰결과 용역(`getOpengResultListInfoServc`)은 `opengCorpInfo`가 채워짐
5. **공동수급**: 낙찰 응답에는 공동수급이어도 **주계약업체 1행만** 온다(계약과 이어진 23건 모두, 이름·사업자번호가 주계약업체와 같음). 낙찰 응답만으로는 공동수급을 알 수 없다. 업체명의 쉼표는 `Co.,Ltd.` 같은 상호 일부
6. **계약정보**: `corpList`는 문서 순서 그대로 `[순번^업체구분^공동도급방식^업체명^대표자명^국적^지분율^채권자명^담당자^사업자번호]`(10칸, 사업자번호는 10번째). 업체구분 `주계약업체`·`도급업체`, 방식 `단독`·`공동`·`분담`·`혼합방식`. **`cmmnCntrctYn`은 믿을 수 없다**(방식이 공동인데 N인 계약이 많음). `ntceNo`는 신체계면 **13자리 공고번호만(차수 없음)**, 구체계는 11자리, 수의계약 등은 빈 값(2일치 596건 중 458건). 6일 창 2,997건(4페이지)
7. **키**: 기존 `NARA_API_KEY`로 낙찰·계약 둘 다 HTTP 200 정상 → `NARA_AWARD_API_KEY`는 당장 필요 없음(있으면 우선 사용)
8. **5년 백필**: 7일 창 건수 표본(최근 2주, 1·2·3·5년 전) 중앙값 1,660건 → 창당 2페이지 × 261창 = **약 522회, 하루 300회면 2일**. 증분(최근 14일)은 하루 4회

## 결정 (P8-b 구현)
- 창: `[start, end)` 7일, 요청은 끝-1분 → 6일 23시간 59분(07 오류 없음). 페이지 999 고정(1000 금지)
- 연결 키: 낙찰 `bidNtceNo`를 그대로 `bids.bid_no`와 잇는다(정규화 함수 불필요, 구체계 11자리는 `bids`에 없으므로 연결 안 됨)
- 고유키: §15.3의 `(bid_ntce_no, bid_ntce_ord, bizno)` 대신 **`(bid_ntce_no, bid_ntce_ord, bid_clsfc_no, rbid_no)`** — 낙찰은 분류·재입찰 단위로 한 행이고, 사업자번호가 없는 낙찰(NULL)도 멱등이어야 하므로. `bizno`는 일반 컬럼
- `g2b_award_rate`는 협상계약이면 대부분 비어 있음(원칙 4 그대로). `is_joint`는 낙찰 수집 때 false, P11 계약 수집이 `corpList` 방식(단독이 아니면 공동)으로 채운다
- 계약 연결: `ntceNo[:13]`(신체계) 또는 `[:11]`(구체계)
- `backfill_years` 기본 5 유지, `G2B_AWARDS_DAILY_BUDGET` 300 유지
