# P12-a 개찰 결과 순위 빈칸 확인 · '우리 투찰 결과(낙찰·탈락)' 제안
- 계기: 사용자 요청(2026-11-17) — '우리 수주 현황'에 낙찰뿐 아니라 떨어진 사업도, 몇 등·누가 이겼고 경쟁사는 어떤지
- 확인 스크립트: `backend/scripts/probe_ranks.py` (G2B 40회, 집계만 출력, 개인정보·사업자번호 저장 없음)
- 표본: 최근 45일 용역 낙찰 40공고 — 협상계약 20, 그 밖(소액수의견적 9·수의시담 5·적격심사 5·최저가 1) 20

## API로 할 수 있는 것 [확인됨, 낙찰정보서비스 1.2 문서]
- 사업자번호(`bizno`) 조건은 '낙찰된 목록 현황(PPSSrch)'에만 있다 → 업체로는 **이긴 공고만** 찾을 수 있다
- 참가업체 전체·순위(`getOpengResultListInfoOpengCompt`)는 **공고번호로 1건씩만** 조회된다
- 회사의 과거 투찰 목록은 없음(사용자 확인) → 우리가 참가한 공고는 개찰 결과를 받아 우리 사업자번호를 찾아야 안다

## 결과
| | 협상계약 | 그 밖 |
|---|---|---|
| 참가 행 | 79 | 498 |
| 순위 있음 / 빈칸 | 48 / 31 | 327 / 171 |
| 빈칸의 비고(`rmrk`) | 협상평가부적격자 31 | 낙찰하한선 미달 169, 전자입찰취소신청 1, 규격서평가부적격 1 |
| 순위 있는 행의 비고 | 정상 48 | 정상 327 |
| 빈칸 행의 투찰금액 / 투찰률 | 31 / 4 | 169 / 169 |
| 종합점수 | 79행 모두 | 없음 |
- 순위는 모든 공고에서 1부터 빈 번호 없이 이어진다(40/40). 모든 행이 순위 있는 공고는 20/40
- **결론: 순위 빈칸은 데이터 누락이 아니라 '부적격·탈락'이고 사유가 비고에 있다.** 순위를 투찰금액으로 추정하지 않는다
- 표시: 순위 있으면 'N위 (유효 k곳 중)', 없으면 '순위 없음 · 사유(낙찰하한선 미달 등)'
- 비고는 개인정보가 아니라 저장 대상(화이트리스트)에 넣는다. → 0011에서 `bid_participants.remark` 추가

## P12 — 우리 투찰 결과 (2026-11-17 사용자 승인, 구현함)
1. **개찰 결과 자동 수집**: 매일 새로 들어온 용역 낙찰 공고(실측 하루 약 240건)의 개찰 결과를 공고당 1회씩 받는다.
   불러온 공고는 다시 부르지 않는다(`bid_participant_fetches`, P11과 같음). 남는 호출로 과거 공고를 최신부터 거꾸로
   (우리 분야 태그·우리가 낙찰한 수요기관 공고 먼저). 예산은 낙찰 몫과 따로 `G2B_OPENINGS_DAILY_BUDGET`(300)
2. **우리 참가 공고** = `bid_participants`에 우리 사업자번호가 있는 공고. 결과는 낙찰 / 탈락(N위) / 부적격(사유)
3. **화면**: '우리 수주 현황'에 '전체·낙찰·탈락' 구분과 결과·순위·낙찰업체 칸. 공고별 상세 페이지 —
   우리 순위·투찰금액·투찰률·점수, 낙찰업체, 참가업체 전체 표(순위·업체·투찰금액·투찰률·점수·비고), 경쟁사마다
   비교 화면(`/competitors/:bizno`)으로 가는 링크. 공고 상세의 '경쟁 구도' 탭과 같은 데이터
4. **한계(화면에 적음)**: 탈락 공고는 자동 수집을 시작한 날부터 쌓이고 과거는 남는 호출만큼만 채워진다.
   개인정보·투찰가 추천·낙찰 예측은 하지 않는다(§15.1)

## 호출량 [일부 미확인]
- 키 한도 하루 1,000회(사용자 확인). 낙찰 몫 300(낙찰·계약·경쟁 구도) + 개찰 결과 300 = 600
- 공고 수집(regular·prespec) 운영 하루 사용량은 [미확인] — 개발 DB의 하루 백필 날 192회. 운영 배포 뒤 관리자 화면 오늘 호출량으로 확인
- 모자라면 공공데이터포털 운영계정 신청(활용사례 등록)으로 한도 상향을 알아본다 [미확인]

## 구현 (P12)
- 마이그레이션 0011 `bid_participants.remark`. 수집기 `--source openings`(`app/awards/openings.py`): 증분 = 최근 14일 낙찰 공고,
  백필 = 그보다 오래된 공고. 둘 다 우리 낙찰 → 우리 분야 태그·우리가 낙찰한 수요기관 → 나머지, 같은 순위면 최신부터.
  G2B 소스 이름 `openings`(같은 오퍼레이션, 예산만 따로), 몫을 다 쓰면 정상 종료. 공고 하나 오류는 건너뛰고 연속 3번이면 멈춤
- timer 순서: 낙찰 증분 → 계약 증분 → 개찰 증분 → 낙찰 백필 → 계약 백필 → 개찰 백필, 시간 상한 1시간
- API `GET /my-bids?result=all|won|lost`(결과·순위·유효 업체 수·우리 투찰·낙찰업체, 수집 현황),
  `GET /my-bids/{no}/{ord}/{clsfc}/{rbid}`(참가업체 전체·비고·업체별 수집된 낙찰 수, 안 받은 공고는 그 공고만 1회 온디맨드)
- 화면: '우리 수주 현황'에 탭 '낙찰 현황'·'투찰 결과'(`?tab=bids`, 결과 `?result=`), 상세 `/my-awards/bids/:no/:ord/:clsfc/:rbid`.
  경쟁 구도 탭도 순위 없는 업체에 비고를 보인다. 공동수급 구성원(대표사가 아닌)으로 참가한 공고는 개찰 결과에 우리가 없어 안 보인다
