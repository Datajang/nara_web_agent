# 맞춤 추천 후보 수·1억 기준, 검색에서 취소공고 제외 (2026-11-17)
- 명세: §4 bids(취소공고), §7.4 맞춤 추천
- 요청(사용자): 추천이 300건을 검토해 느림 → 20~50건(기본 20). 다른 화면에 다녀오면 결과가 사라짐.
  모든 공고 검색에서 취소공고 제외. 맞춤 추천은 1억 미만 기본 제외, 원하면 체크박스로 포함.

## 확인한 것 (개발 DB, 최근 30일)
- 일반 15,204건 중 취소공고 1,163건(7.6%), 1억 미만 7,997건, 예산 없음 3건. 사전규격은 취소공고 0건.

## 결정
- 취소공고: `build_query`와 관심 공고 질의에 `not_cancelled()`(raw.ntceKindNm IS DISTINCT FROM '취소공고').
  검색 탭·추천·어시스턴트·관심 공고 모두 적용. 북마크·지난 기록·번호로 열기는 카드에 표시만(P1 결정 변경).
- 추천 후보 수: `RecommendIn.candidates` 20~50(기본 20), 화면 20·30·40·50 세그먼트, top_n도 같은 값.
  어시스턴트 recommend_bids는 300건 상한 그대로.
- 1억 기준: `RecommendIn.include_small`(기본 false)이면 `budget_min=1억`(예산 미상도 빠짐, 3건 수준).
  관심 공고 '1억 원 미만 공고도 보기'와 같은 기준·문구. 어시스턴트 도구는 제한 없음.
- 결과 유지: pinia `recommend` 스토어(SSE keepAlive)로 화면 이동에도 진행·결과 유지.
  새로고침·다른 기기는 `search_runs`의 마지막 recommend 기록과 조건(query의 candidates_max·
  custom_keywords·include_small)을 불러온다. 다른 계정으로 바뀌면 비운다.
