# 어시스턴트 답 마크다운 표시 · 금액 억·만 읽기 오류 (2026-11-18)
- 명세: §8.6 어시스턴트 도구, §10.4 MarkdownView·ChatMessage
- 요청(사용자): 답의 `**…**`가 그대로 보임 → 굵게·표로. 실측 오류: 302,727,273원을 '약 30 억 2700 만원'으로 씀(10배)
- 원인: 프롬프트가 '억·만으로 바꾸지 마라'고 해도 7.8B 모델이 직접 바꾸다 자릿수를 틀림. 검색 답은 숫자 검증 대상이 아니었음

## 결정 (구현함)
1. 도구 결과 금액에 맞는 읽기를 같이 준다: `302,727,273원 (약 3억 272만 원)` (`app/bids/meta.py` money_text, 만 미만 버림).
   요약·분석 입력(budget_text)은 그대로 — 캐시·프롬프트 버전 영향 없음
2. 도구를 쓴 답은 모두 검증 뒤 내보낸다(낙찰·경쟁사 도구와 같은 흐름: 확인 → 1회 다시 쓰기 → 틀린 문장 빼기).
   낙찰·경쟁사 도구는 모든 숫자, 그 밖(공고 검색 등)은 **금액만**(억·만 단위 또는 '원'). 건수·날짜와
   '10억 이상'·'5천만 원 미만' 같은 구간 경계, 질문·도구 인자에 나온 금액은 통과 (`unsupported_money`)
3. 프롬프트: 금액은 도구 결과 표기 그대로, 답은 마크다운(소제목 굵게, 공고 2건 이상이면 표)
4. 화면: 도우미 답을 MarkdownView(marked + DOMPurify)로, 표·목록·굵게 스타일은 `styles/base.css` `.markdown`.
   사용자 글은 해석하지 않고 그대로. 도우미 말풍선 폭 880px

## 실제 모델 확인 (vLLM, 개발 DB)
- '데이터 구축 공고 10억 이상/그 외로 정리' → 20건 표, 금액 20개 모두 정확(경고 0). b1557 → `281,818,181원 (약 2억 8,181만 원)`
- 트레이드오프: 검색 답도 다 만든 뒤 한 번에 보인다(그동안 '숫자를 맞춰 보고 있어요' 상태 표시)
