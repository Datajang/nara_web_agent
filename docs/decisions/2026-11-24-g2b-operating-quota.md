- 계기: 사용자가 쓰는 API 전부를 운영계정으로 바꿔 하루 10만 회가 됨(2026-11-24). "필요한 정보를 최대한"

  낙찰 중 추정가격(낙찰률)이 있는 건 3.8%(공고가 90일뿐이라). 속도: 개찰 약 1.5~3.8회/초, 공고 백필 하루치 약
  8~25초, 계약 1회 약 9초. 수집기에는 같은 소스 동시 실행 잠금이 없다(커버리지는 겹쳐도 하루 이내로 스스로 회복)

  awards·opening_compt·openings는 같은 낙찰정보서비스라 '낙찰 몫 + 개찰 몫 − 계약'이 10만 안쪽(최대 약 9.2만)

- 따라잡기(한 번, 2026-11-24 07:00 UTC, systemd-run `nara-catchup-*`):
  공고 `backfill --source regular --days 1826` → `scripts.reclassify_awards`(낙찰률 다시 채움),
