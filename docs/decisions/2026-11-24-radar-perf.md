# 경쟁사 레이더 속도 개선 (필터 없을 때)
- 명세 위치: §15.5(겹침도), §15.6 `GET /competitors/candidates`
- 계기: 레이더 첫 화면(분야·기관 필터 없음)이 운영에서 약 3.5초. 낙찰 수집을 6년(63만 건)으로 늘린 뒤 느려짐
- 원인: `_CANDIDATES_SQL`이 낙찰 전체로 업체×기관·업체×분야 집계를 만든 뒤 상위 N개만 읽었다
- 결정: 필터가 없을 때만 두 단계로 나눈다(`_candidates_unfiltered`)
  1. `_OVERLAP_SQL`: 우리 기관·우리 분야에 걸린 낙찰만 색인으로 골라(hit) 겹침도 점수를 모두 낸다
  2. `_COUNTS_SQL`: 점수 순으로 100곳 → 200곳 → … 낙찰 건수·이름·관심 여부를 세고, 2건 미만은 뺀다.
     동점 묶음은 끊지 않아 '점수 → 낙찰 수 → 사업자번호' 순서가 한 번에 센 것과 같다
  - 필터(분야·기관)가 있으면 걸리는 낙찰이 적어 원래 SQL 그대로
- 확인: 운영 DB에서 새 함수와 옛 함수 결과 일치, 3.5초 → 0.35초. 테스트 `test_candidates_order_survives_paged_counts`
  (묶음을 1곳씩 잘라도 순서·제외가 같음)
