# 낙찰·계약: 페이지 겹침으로 행이 조용히 빠짐 → 창을 쪼개 한 페이지씩
- 명세 위치: §15.4(창 완결성), `docs/g2b/AWARDS.md`
- 계기: 낙찰 백필이 KST 2017-04-13~19 창에서 '1855/1856건 (페이지 3)'으로 멈춤(2026-11-25 timer)
- 확인(`scripts/probe_awards_gap.py`, 운영 키, G2B 17회):
  - 7일 창 999행 페이지: 1,855행 중 고유 1,853 — 2행 중복(1·2페이지 겹침), 대신 다른 2건이 빠짐
    (하루씩 받으면 1,855건 모두 옴, 날짜가 다른 같은 키는 없음) → **건수 검사로 못 잡는 누락**
  - 2017-04-17: 한 페이지(402 ≤ 999)인데 401행 → G2B 결함, 매번 같음. 오전 173건 중 172행
  - 시·분 필터 작동: 낙찰 2017-04-17 오전 173 + 오후 229 = 하루 402, 계약 697 + 1,497 = 2,194,
    rgstDt가 각 범위 안
- 영향: 7일 창이 2페이지 이상인 낙찰(거의 전부)·계약(전부) 창에서 몇 건씩 빠졌을 수 있다(이 창 0.1%)
- 결정(사용자 승인): `STRICT_PAGING`(awards·contracts)은 `pageNo=1`만 쓴다. 건수가 page_size를 넘으면
  창을 시간으로 ⌈건수/(page_size×0.8)⌉ 조각으로 나눠 다시(재귀). 한 페이지에서 누락이
  max(1, 건수/1000) 이하면 경고 로그 + collector_runs.error('G2B 행 누락 허용 …', status ok)로 넘어가고,
  넘으면 G2BIncomplete. 호출 수는 큰 창마다 첫 1회가 더 든다
- 복구: `python -m app.collector refetch --source awards|contracts --from --to` — 커버리지 안을 다시 받아
  upsert(경계 그대로). 낙찰 전체 약 85만 행 → 약 1,500~2,500회(낙찰 몫 15,000 안)
- 하지 않은 것: 공고(regular)·사전규격 — 같은 현상인지 미확인, 엄격 검사 대상이 아니라 그대로
