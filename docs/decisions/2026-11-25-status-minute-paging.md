# 개찰 상태: 1분에 999행이 넘는 창 (2026-11-25)

## 문제
운영 백필(`backfill --source status --days 2192`)이 2,319회·820,323행을 받은 뒤
2021-11-25 11:00(KST) **1분 창 1,159행**에서 멈췄다. 창은 1분보다 잘게 못 쪼개고,
낙찰·계약 결함(페이지 넘김 시 행 겹침·빠짐, 3c893cc) 때문에 STRICT 소스는 한 페이지만 받았다.
커버리지는 2021-11-30 ~ 지금(5년)까지 남았다.

## 확인 (`backend/scripts/probe_status_minute.py`, 호출 4회)
그 1분을 999행씩 2페이지로 두 번 받음:
- 회차마다 999 + 160 = 1,159행, 고유 키 1,159, 겹침 0
- 두 회차 순서 같음 → 개찰 상태는 1분 안 페이지 넘김이 안정적

## 결정
- 1분 창이 한 페이지를 넘을 때만 페이지를 넘긴다(`G2BClient._page_minute`). 똑같은 행은 하나로 치고,
  고유 행이 건수보다 허용치(1행·0.1%) 넘게 모자라면 지금처럼 실패. 낙찰·계약도 같은 길이지만
  겹치면 실패로 남아 조용히 빠지지 않는다.
- 상태 백필 시작은 `max(org_settings 연수, 공고(regular) 수집 시작)`. 운영 backfill_years=10이라
  공고가 없는 2020-11 이전을 받는 낭비(수천 회)를 막는다.
