# 협상 공고 제안서평가 일시 (2026-11-27)

## 문제
결과 메일의 '결과 대기' 5분 확인(rc24)이 협상에의한계약 공고에서 헛돈다. 운영 DB(개찰 30~120일 전 일반공고)로 잰
개찰 → 개찰완료 입력: 협상 5,266건 중앙값 **8일**(p90 21일), 그 외 15,362건 중앙값 30분(p90 15시간).
제안서평가 뒤에 순위가 입력되기 때문이다. 예: R26BK01824103(개찰 11-24, 평가 12-02 09:30)이 rc24까지 148회 확인.

## 확인 1 — 평가 일시는 어디에 있나
- Open API 문서 4종(입찰공고 1.3·낙찰 1.2·계약 1.0·사전규격 1.0)의 날짜 필드·오퍼레이션을 전부 봤다: **없음**
- 나라장터 웹 공고 상세(PNPE027_01) '입찰진행정보'에 있다. 헤드리스 브라우저로 화면이 부르는 주소를 기록:
  `POST https://www.g2b.go.kr/pn/pnp/pnpe/ItemBidPbac/selectItemAnncMngV.do`
  본문 `{"dmItemMap":{"bidPbancNo":"R26BK01824103","bidPbancOrd":"000"}}` (JSON)
- **로그인·쿠키·세션 없이** curl 한 번으로 200, 약 23KB JSON. `ErrorCode` 0
  - `dmEvlStepMap.evlDt` = `2026/12/02 09:30` (KST), `evlMaagSeNm` 평가 주관(조달청·수요기관)
  - `dmItemList1` = 입찰진행정보 표. `subject`='제안서평가' 행의 `startDt` = `2026/12/02 09:30:00`
- robots.txt는 Googlebot의 한 경로만 막는다. 이 주소는 막지 않는다

## 확인 2 — 평가 일시와 결과의 간격 (`backend/scripts/probe_eval_date.py`, 호출 50회·1초 간격)
- 협상 공고 무작위 25건: 평가 일시 있음 2건, 없음 23건. 없는 것은 모두 평가 주관 **수요기관**,
  표에 '수요기관 담당자에게 문의'(날짜 비어 있음)
- 조달청이 공고한 협상 공고 25건(`pps`): 평가 일시 있음 8건(모두 주관 조달청), 없음 17건(수요기관 16·조달청 온라인 1)
  - 조달청 평가 8건 모두 **평가 시작 2.1~4.0시간 뒤** 개찰완료 입력(중앙값 3.6시간). 평가 전 결과 0건
- 수요기관 평가인데 날짜가 있던 2건은 +3.5시간·+306시간(믿기 어렵다)

## 결론
- 평가 일시는 웹 주소 하나로 받을 수 있다. 다만 협상 공고의 다수(수요기관 평가)는 날짜가 없다
- 조달청 평가 공고는 평가 시작 뒤 몇 시간 안에 결과가 나온다 → 그 전에는 부를 필요가 없다
- 날짜가 없거나 웹 호출이 실패하면 낙찰방법만으로 판단해야 한다(개찰 뒤 며칠~몇 주)
- 웹 화면용 내부 주소라 예고 없이 바뀔 수 있다. 실패는 경고 로그 + 날짜 없음과 같이 처리한다

## 결정 (사용자 승인 2026-11-27)
- 협상 공고(낙찰방법 `sucsfbidMthdNm`에 '협상')의 결과 대기 감시는 웹에서 평가 일시를 읽어 `bid_result_watch.eval_at`(0015)
  - 평가 일시 있음: 그때까지 G2B를 부르지 않고, 평가 시작부터 24시간 5분 → 3시간. 60일은 평가 시작부터 센다
  - 없음(수요기관 평가·웹 실패): 개찰 뒤 30분. 그 외 공고는 그대로(개찰 뒤 7일 5분)
- 웹 호출: 처음 한 번 + 결과 대기 동안 하루 한 번(정정·연기). 실패는 경고 로그, 1시간 뒤 다시. 1초 1건, 실행당 20건·40초
- 코드 `app/g2b/web.py`(G2BWebClient), `app/results/evaldate.py`(타이머에서 감시 맞추기 뒤·확인 전)
