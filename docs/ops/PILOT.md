# 파일럿 2주 진행표 (docs/ops/OWNER_GUIDE.md 9단계)

대상 5~10명(입찰 담당 위주), 기간 2주. v1은 그대로 둔다(CUTOVER §4).

## 시작 전 (운영자)
- `send-test-mail`로 메일 확인, 관리자 계정으로 로그인, 공고 검색이 되는지 확인.
- 팀장 역할을 맡을 사람 1명을 정해 먼저 가입시킨다 → 설정 → 팀에서 팀을 만들고 초대 링크를 받는다.

## 참가자에게 보낼 안내 (복사해서 메일·메신저로)
> 나라장터 입찰 공고를 찾아 요약·분석해 주는 사내 도구를 2주간 시범 운영합니다.
> 1. 주소 `https://<접속 주소>` 에서 회사 메일로 가입 → 인증 메일의 링크 클릭 → 관리자 승인 후 로그인
> 2. 처음 화면에서 **관심 키워드 3개 이상**(예: 클라우드, 데이터 플랫폼, AI)을 정하면 '관심 공고'에 맞는 공고가 마감 순으로 뜹니다
> 3. 팀 초대 링크(따로 보냄)를 누르고 '팀에 들어가기' — 팀원이 만든 분석을 같이 볼 수 있습니다
> 4. 설정 → 프로필에 팀 소개(역량·실적)를 적어 두면 공고의 '분석하기'가 우리 팀 기준으로 적합도를 판단합니다
> 5. 공고 상세에서 '분석하기'(처음 1~3분) → 요약·요구사항·평가 배점·일정·적합도 확인. 첨부파일은 이름을 누르면 내려받기
> 6. 결과 아래 **'도움이 됐어요' / '아쉬워요'** 를 꼭 눌러 주세요. '아쉬워요'는 이유(사실과 달라요·빠진 내용이 있어요 등)를 골라 주세요
> 문의: <운영자 연락처>

## 매주 (운영자, 10분)
```bash
sudo -u nara env NARA_ENV_FILE=/etc/nara/nara.env /opt/nara/venv/bin/python -m app.ops.feedback_report --days 7
```
- 결과(대상별 👍·👎, 👎 사유 상위 3, 👎 많은 공고)를 그대로 Claude에게 붙여 넣고 "원인 찾아서 고쳐 줘".
  보고에는 공고 번호·제목과 집계만 있고 누가 무엇을 썼는지는 없다(§9).
- 관리자 화면 '사용량'에서 사용자 수·분석 수·LLM 오류도 같이 본다.

## 2주 뒤 결정
| 기준(제안) | 계속 | 고친 뒤 재시범 |
|---|---|---|
| 분석 👎 비율 | 30% 이하 | 30% 초과 |
| 주 1회 이상 쓴 사람 | 참가자 절반 이상 | 절반 미만 |
| 치명 오류(틀린 마감일·금액으로 판단) | 0건 | 1건 이상 |
계속이면 전체 공지 → v1 종료(CUTOVER §4 마지막 줄).
