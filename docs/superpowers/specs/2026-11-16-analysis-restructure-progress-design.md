# 분석 결과 개편 + 진행 로딩바 — 설계 (2026-11-16)

## 왜
- 공고 상세에서 '요약' 카드(일정·예산·계약·평가·자격·핵심 요구사항)와 '분석' 결과가 같은 내용을 되풀이한다.
- 분석은 "이 사업이 무엇인지"와 "우리 팀과 얼마나 맞는지(객관적 판단), 무엇이 필요한지"에 집중해야 한다.
- 요약+분석이 공고당 1분 30초~6분(골든셋 v9) 걸리는데 화면은 단계 이름만 보여 준다.

## 목표 / 하지 않을 것
- 목표: 분석에서 겹치는 4개 섹션 제거, 사업 이해·팀 적합도·필요한 것 중심으로 재구성,
  프로필이 짧거나 판단에 필요한 정보가 없으면 간략 분석 + '프로필을 더 상세히' 안내, 실제 진행률 로딩바.
- 하지 않음: 요약 카드 구성 변경, 프로필 DB 구조 변경(팀 소개 글 하나 그대로), 분석 점수 흔들림 추가 수정.
- 실패로 볼 것: 프로필이 빈약한데 그럴듯한 상세 판단을 지어내는 것. 남은 시간을 실제보다 짧게 약속하는 것.

## 접근 (대화에서 결정)
- 순서: 로딩바(A) 먼저, 분석 개편(B) 다음. 서로 독립이라 따로 커밋.
- 분석 입력: 요약 첫 단계(조각별 FileFacts)가 이미 뽑는 `purpose`·`scope`를 최종 요약에 남겨 분석에 넘긴다.
  (기각: 분석에 제안요청서 원문 조각을 직접 넣기 — 12K 토큰 × 최대 12조각이라 한 번에 못 넣고 시간이 배로 듦)

## A. 진행 로딩바
- 백엔드: 요약 map 단계에서 조각 하나가 끝날 때마다 `status(summarize, progress={done,total})`
  (§6.4에 이미 있는 필드). 다른 단계는 지금처럼 시작 때 한 번.
- 분석 단계는 LLM 한 번이라 셀 수 없다 → `status(analyze)`에 `expected_s`(설정값, 측정해서 정함)를 싣는다.
- 화면(ProgressSteps 아래 막대 하나): 파일·추출 0→10%, 요약 10→75%(조각 done/total),
  분석 75→95%까지 expected_s 동안 천천히 채우고 결과가 오면 100%.
  옆에 '경과 1분 20초'와 '약 N분 남음'(요약 중엔 조각 속도로 추정, 분석 중엔 expected_s 기준,
  넘기면 '거의 다 됐어요'로 바꿈 — 시간 약속을 하지 않음). `role="progressbar"`, aria-valuenow.
- 캐시 적중(즉시 결과)·다른 요청 처리 중(in_progress)일 때는 막대를 띄우지 않는다.

## B. 분석 결과 개편 (PROMPT_VERSION v10)
화면·스키마 순서:
1. 사업 이해 `understanding`: 목적·배경(`purpose`), 과업 범위·주요 기능(`scope` 목록),
   수행 조건(`conditions` 목록: 산출물·투입 인력·기간 등 — 금액·날짜는 요약 카드에 있으니 쓰지 않음)
2. 우리 팀 적합도 `fit`: 점수·판정·근거(지금과 같음, strengths·gaps는 3번으로 옮김)
3. 우리 팀에 필요한 것 `team_needs`: 이미 갖춘 것 `have` / 보완할 것 `need`
   (인력·기술·실적·자격·협력사). 프로필에 적힌 사실만 근거로.
4. 프로필 보완 `profile_missing`: 이 공고를 판단하는 데 프로필에 없던 정보(0~5개, 예: 'PM 자격 보유 여부')
5. 리스크·유의사항(우리 팀 입장) 6. 다음 할 일 7. warnings
- 빠짐: requirements, evaluation, schedule, budget_contract(요약 카드에 있음).
- 프로필 충분성(서버가 정함, 테스트 가능): 정규화한 팀 소개가 `profile_min_chars`(기본 200자) 미만이면
  `brief` → 프롬프트에 '간략히(have·need 각 3개 이하)' 지시.
  화면은 brief이거나 profile_missing이 있으면 3번 위에 안내:
  "프로필 정보가 더 상세히 있으면 정확한 분석이 가능해요" + 빠진 정보 목록 + [프로필 고치기] 링크.
- 프로필 화면: 팀 소개 안내 문구를 '주력 분야·기술, 인력 규모·주요 자격, 최근 3년 유사 실적,
  보유 인증·면허, 하지 않는 일'로 구체화(분석 정확도와 연결됨을 한 줄로).
- 요약 스키마에 `scope: list[str]` 추가(reduce에서 조각별 scope를 합침). 요약 카드에는 표시 안 함.
- 예전 분석(내 기록): 결과 JSON에 `understanding`이 없으면 지금 화면 그대로 보여 준다(옛 컴포넌트 유지).
  저장된 마크다운은 그대로. 새 render_markdown은 새 순서.

## 빌더에게 맡김 (내 판단으로 정한 것은 위에 표시)
- `expected_s` 기본값: 개발 서버에서 분석 단계만 몇 건 재서 정한다(설정값).
- `profile_min_chars` 200은 출발값. 막대 단계별 비율은 실측 보고 조정 가능.
- 필드별 글자·개수 상한(Cap)은 기존 규칙에 맞춰 정한다.
