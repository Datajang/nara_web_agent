# 마감 공고 사유 표시 — 짧은 설계 (2026-11-26)

## 왜
마감된 공고 카드에 '마감'만 보인다. 날짜만 지난 것인지, 유찰·낙찰·재입찰인지 **목록에서 한눈에** 보고 싶다(사용자, 2026-11-25).
비목표: 사유로 거르는 필터, 재공고 연결, 알림(결과 메일이 따로 있다).

## 접근 (사용자 선택: A)
- **A. 개찰 상태를 기간으로 모아 두고 카드에서 보여 준다(채택)**: `getOpengResultListInfoServc` 하루 1회 호출로 용역 공고 전체의
  상태. 낙찰은 이미 모은 `bid_awards`. 화면은 G2B를 부르지 않는다
- B. 있는 데이터만(낙찰·개찰일): 유찰·재입찰이 '결과 대기'로 남아 목적에 맞지 않음 → 안 함
- 카드마다 G2B 조회: 한 화면 수십 건이라 느리고 호출이 많음 → 안 함

## 무엇
- 마감된 일반공고 카드(검색·관심 공고·추천·보관함, 상세 화면도)에 사유 배지 하나. 진행 중 공고는 지금 그대로
- 판정 순서(공고의 현재 차수 기준, 분류마다 마지막 재입찰 행):
  1. 취소공고 → '취소'(지금 배지 그대로)
  2. 낙찰 행 있음 → **'낙찰 · {낙찰 업체}'** (분류가 여럿이면 첫 업체 + ' 외 N')
  3. 모든 분류 유찰 → **'유찰 · {무응찰|단독응찰|낙찰하한선 미달}'**(문구를 못 묶으면 '유찰')
  4. 개찰완료 있음 → **'개찰완료 · 1순위 {업체}'**(낙찰자 심사 중)
  5. 재입찰·재시담 → **'재입찰'**
  6. 상태 없음: 개찰일이 미래 → **'개찰 전 MM/DD'**, 지났으면 **'결과 대기'**, 개찰일 없음 → 지금처럼 '마감'만
- 사전규격은 마감 뒤 **'의견 마감'**
- 색: 낙찰 초록 · 유찰·취소 빨강 · 개찰완료·재입찰 주황 · 개찰 전·결과 대기 회색. 업체 이름은 길면 말줄임(전체는 title)

## 데이터·수집 (`docs/decisions/2026-11-26-opening-status-bulk.md`)
- 새 테이블 `bid_opening_status`(Alembic 0014): 키 (공고번호·차수·분류·재입찰), 상태, 개찰일시, 입력일시, 참가 수,
  결과 문구(200자), 1순위 업체명·사업자번호. 공고번호 색인
- 받기: KST 하루씩 1쪽(999행, 넘으면 반나절로). 같은 키는 덮어쓴다(upsert)
  - 증분: 공고 수집 10분 타이머 끝에 어제·오늘 2회(입력 지연 최대 약 24시간)
  - 백필: 낙찰 타이머(04:30)에서 6년, 오래된 쪽으로. 커버리지는 낙찰 수집과 같은 방식
  - 예산 몫 `G2B_STATUS_DAILY_BUDGET`(기본 3,000, 낙찰정보 서비스). 증분 약 100회/일 + 백필 약 2,200회(한두 날)
- API: `BidCard`(상세 `BidDetail`도)에 `outcome`(종류·업체명·유찰 사유·개찰일시, 진행 중이면 null). 화면 문구는 프론트가 만든다

## Claude 판단
- 낙찰·상태는 공고의 **현재 차수**(raw `bidNtceOrd`)만 본다(정정 전 차수의 결과를 섞지 않음)
- 1순위·낙찰 업체 이름은 개찰 결과·낙찰 API 문자열 그대로(우리 회사 표시는 하지 않음)
- 결과 메일 감시는 이번에 바꾸지 않는다(이 테이블을 나중에 쓸 수 있음)
