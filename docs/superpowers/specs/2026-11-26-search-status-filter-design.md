# 공고 검색 상태: 마감·유찰 + 빠진 마감 공고 알림 (2026-11-26)

## 왜
마감됐지만 개찰 결과가 아직 없는 공고(D-day 지난 공고)는 상태 기본값 '진행중'에 걸려 검색에서 조용히 빠진다.
직원들이 "왜 안 나오지?"를 찾다 겨우 '상태' 옵션을 발견한다(운영 피드백). 옵션 추가는 그다음.

## 목표 / 비목표
- 목표: 찾는 공고가 상태 때문에 빠졌으면 결과 자리에서 바로 알고 한 번에 보이게 한다. 상태에 마감·유찰 추가
- 비목표: 기본값 변경(평소 검색은 그대로 '진행중'), 추천·어시스턴트 도구의 상태 값(그대로 open/all), 재공고 연결
- 반(反)목표: 평소 검색 결과에 마감 공고가 섞이는 것, 화면 요청에서 G2B 호출이 느는 것

## 접근 (사용자가 B 선택)
- A. 옵션만 추가: "왜 안 나오지"가 그대로 → 탈락
- **B. 옵션 추가 + 빠진 마감 공고 건수 알림** ← 선택
- C. 기본값 '전체': 평소 검색에 마감 공고가 섞임 → 탈락

## 설계
- 상태: **진행중(기본) · 마감 · 유찰 · 전체**. API `status: open | closed | failed | all`
  - 마감 = 마감일 지남(유찰·낙찰·결과 대기 모두 포함). 마감일 없는 공고는 진행중 쪽
  - 유찰 = 카드 배지와 같은 규칙(`docs/BID_OUTCOME.md`): 현재 차수의 낙찰 행 없음 + 분류마다 마지막 재입찰 행이
    모두 '유찰'. SQL EXISTS/NOT EXISTS로 DB에서 거른다(`bid_opening_status`). 사전규격은 빠짐
  - 취소공고는 지금처럼 어느 상태에서도 뺀다
- 알림: `status=open`일 때만, 같은 조건에서 마감된 공고 수를 DB에서 한 번 더 센다 → `SearchResultOut.hidden_closed`(int, 그 밖엔 0)
  - 결과 위: "마감된 공고 N건은 빠져 있어요 [마감 공고도 보기]" → 누르면 상태 '전체'로 다시 검색
  - 진행 중 결과 0건 + N>0: 빈 화면 대신 "진행 중인 공고는 없고 마감된 공고 N건이 있어요 [보기]"
  - 카드는 이미 있는 사유 배지(결과 대기·유찰·낙찰 등)로 구분된다
- 기간: 상태와 무관하게 지금처럼 공고일 기준(기본 14일). 유찰을 골라도 기간을 바꾸지 않는다 [내 결정: 놀라지 않게]
